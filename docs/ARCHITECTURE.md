# Architecture

macOS 14 is the deployment floor. Swift 6 strict concurrency is enabled. The app target is the composition/lifecycle root; local Swift Package products provide module boundaries. GRDB 7.8.0 is the only external dependency (MIT).

| Module | Responsibility |
| --- | --- |
| SottoApp | Menu bar, app lifecycle, native Settings window |
| SottoUI | Observable coordinator, settings persistence, CGEvent shortcut, NSPanel, native views |
| SottoAudio | AVAudioEngine capture, RMS, modern/legacy Apple speech, optional OpenAI Realtime, typed transcripts, voice timing, microphone selection, synthesis interface |
| SottoAgent | Explicit state machine, bounded model/tool execution loop, event stream |
| SottoProviders | Provider protocol, capability catalogs, OpenAI SSE and native Ollama NDJSON, typed function calls |
| SottoTools | Tool protocol, JSON values, schemas, registry, results, risks, required capabilities |
| SottoIntegrations | NSWorkspace, Spotify Apple Events, Spotlight, EventKit, foreground-app foundation |
| SottoSecurity | Exact-argument single-use approval continuations, schema validation, Keychain |
| SottoPersistence | Actor-isolated GRDB queue, migrations, retention, deletion |

## Lifecycle

The MainActor coordinator owns one voice session and its tasks. UUIDs reject late callbacks after cancellation. Activation shows the nonactivating panel before permission checks/audio startup; releasing during startup is remembered. Audio capture stops before final recognition is awaited. Provisional text may prepare inference under the selected processing consent, but only a final, explicitly submitted request may execute tools. Timeouts do not silently submit partial speech. The audio callback converts PCM and reports RMS; UI updates are explicitly dispatched to MainActor. See [real-time voice](REALTIME-VOICE.md) for the audit, research and lifecycle.

ActivationShortcut stores one validated key/modifier binding. A shared native NSButton recorder captures focused AppKit key/flags events, suspends the global listener while editing and restores it on commit, Escape or focus loss. Legacy modifier presets/key choices migrate without retaining toggle-to-talk. ShortcutGesture is a pure state machine: first press begins capture immediately; long holds submit on release; short releases wait for a second press using macOS's double-click interval (at least 250 ms). Physical CGEvent timestamps determine tap duration, independently of callback delivery delay. A timely second press latches the same audio session into hands-free mode. Its releases and further shortcut presses cannot submit; the capsule's Send action does. Cancel, failure, manual submit, shortcut changes and shutdown clear pending gesture work. The 55-second capture limit discards audio rather than submitting it.

The MainActor Apple facade selects installed SpeechAnalyzer/SpeechTranscriber on macOS 26+, otherwise the existing legacy provider. ModernSpeechWorker owns analyzer preparation, progressive range results, bounded input and finalization. RealtimeMicrophone owns modern/cloud AVAudioEngine capture; AppleSpeechWorker retains the legacy engine path. The modern path needs microphone access, not the legacy Speech Recognition authorization. SpeechRecognitionProvider keeps recognition separate from reasoning; optional OpenAI Realtime uses the same start/update/finish/cancel interface with independent audio consent. Synchronous device calls cannot block capsule rendering or shortcut callbacks. A lock-protected per-session token suppresses stale buffers/results and keeps teardown scoped to its original session. Engines are created only after explicit activation; there is no continuous microphone capture or idle audio prewarming. Event-driven microphone inventory is reused when starting capture. The capsule's hosting tree is laid out once at launch; activation orders that prepared panel before deferred content measurement.

General's explicit press-to-toggle setting uses the same activation binding and bypasses hold/double-tap interpretation. The new `pressToToggle` persistence key preserves old hold-mode migrations. VoicePreparationController schedules inference after acoustic and transcript stability, with two attempts/eight-second budgets. PreparedAgentTurn binds output to words, context, provider/model/destination/local day and a 15-second lifetime. AgentRuntime.prepareTurn has no integration, gate or execution path. AgentRuntime.run can reuse matching output after finalization, then applies ordinary validation/authorization before any tool action. Native deterministic requests skip speculative inference. Context/privacy changes, cancellation and shutdown discard drafts.

Audio configuration notifications are transferred from the engine's internal notification queue to the audio actor. AudioConfigurationGuard compares the actual Audio Unit input device and stream format with the selected input signature. An unchanged running input continues; a stopped engine with the same input can restart without clearing recognition buffers. Format changes may rebuild the tap only before any audio buffer is accepted. Input-device changes, mid-recording format changes, invalid input and exhausted recovery budgets discard the recording. Each session permits at most two repair attempts. Startup remains pending until the first valid audio buffer, with a five-second no-audio timeout; cancel resumes pending continuations and old queued startups cannot reset a newer session.

The reserved ask_user tool pauses a turn when required information is missing. It emits a question rather than a successful action, returns the call/result context, and resumes when the user speaks a reply. Do not register an integration under the reserved ask_user identifier.

The agent consumes streaming provider output and only executes complete, decoded function calls. It validates against the registered schema, asks the trusted gate for authorization, checks cancellation, invokes a native adapter, and sends the actual result/error back to the model. It allows at most eight provider rounds per request and limits output tokens per round. The UI logs successful results and failures independently of prose. No evidence means the panel explicitly reports no action performed.

The gate determines policy from compiled tool metadata, never model flags. Permission prompts happen in adapters using native APIs; denial is a real failure. Required capabilities are declarative metadata; each adapter enforces the underlying OS authorization. There is no generic permission override. A future plugin loader must not accept unreviewed metadata as a security boundary.

## Adding a tool

Implement the `Sendable` Tool protocol with a unique identifier, short description, strict object input schema (all properties required for OpenAI strict mode), output schema, risk, capabilities, and an async throwing execution method. Register it in NativeTools.registry. Use argument enums and native APIs; never interpolate model text into executable scripts. Throw on permission denial, missing app, malformed input, or unverified failure. Return evidence, not optimistic success. Preserve Task cancellation before side effects. Classify sending, destructive, or sensitive write operations as consequential. Add tests proving invalid inputs and denied/cancelled approval cannot produce side effects.

Use MainActor for AppKit/EventKit handles; map non-Sendable framework objects to immutable data inside callbacks before crossing executors. Long-running integrations should use cancellable asynchronous APIs rather than blocking MainActor. Spotify uses a bounded helper process on a dedicated serial queue; fixed action enums select reviewed scripts. Timeout/cancellation terminate the helper, pipe output is capped, and play/pause requires valid state readback. No script runner is exposed to the model.

## Adding a provider

Implement ReasoningProvider.models and stream. Preserve the message/tool-call/tool-result chain; support cancellation via AsyncThrowingStream termination. Never enable tools for an unsupported model. Map authentication, rate limits, transport errors, incomplete streams and malformed outputs into failures. Authenticate explicitly with user-supplied credentials or an officially documented OAuth flow. Never inspect browser credentials or another app's auth files. Do not silently reroute private context to a fallback vendor.

OpenAI and Ollama share the canonical runtime history. OllamaConversation translates assistant/function-call/function-result entries into native assistant/tool messages, preserving result roles and unique call identifiers. Its bounded NDJSON decoder buffers tool calls until a valid completion record, rejects truncation, and retains model thinking metadata only for subsequent local rounds. AgentRuntime checks cancellation after stream termination before interpreting or executing output.

OllamaEndpoint permits only root loopback URLs. A separate ephemeral URLSession disables proxy routing, cookies and redirects, carries no credentials, and bounds metadata/stream sizes. Native model capabilities and advertised cloud metadata are checked during discovery and again before each inference body is sent. The external runtime must also disable cloud features for strict local operation. See [LOCAL-MODELS.md](LOCAL-MODELS.md) for limits and tests.

ProviderSettingsControls is shared by Setup and AI Providers. Preferences stores backend and model choices separately; older settings decode to OpenAI. LocalProviderConnection owns cancellable discovery and stale-operation suppression without credential access. AppModel snapshots the destination for each request, clears conversation and cancels active work when it changes, and reads Keychain only on the OpenAI branch. Remote consent applies to OpenAI; Apple Speech processing remains an independent choice. Neither provider automatically falls back to the other.

For MCP, expose tools through the same registry and approval boundary. Do not let remote server metadata lower local risk decisions. For Codex, see PROVIDERS.md before attempting integration.

## Platform constraints and performance

MicrophoneCatalog observes Core Audio device and default-input changes without polling. Preferences persists stable UIDs as preferences, with system/remaining-input fallback. AppModel snapshots the active device, discards interrupted words and permits bounded fresh-capture recovery after input loss; sleep cancels. Native permission state refreshes on application activation. Modern speech readiness counts without a legacy Speech grant. Setup offers native commands without a reasoning account; flexible requests require available intelligence and destination-specific consent. Global keyboard access is optional.

The app is intentionally not App Sandbox enabled: it automates installed apps and searches user-authorized files. Hardened runtime audio-input and Apple Events entitlements are included. Native TCC prompts gate microphone, speech, Reminders and Spotify Automation; the passive keyboard event tap needs Input Monitoring. No AX or screen permission is requested. PermissionCenter separates not-requested, denied, restricted, allowed and system-managed states. Recovery actions open the relevant native pane; prompts originate only from explicit user actions or requested tool use. No polling is used at idle. Capture timeout, recognition timeout and context expiry tasks sleep and are cancelled on lifecycle changes.

The `org.sotto.mac` / `latency` log records startup/panel ordering. `voice-timing` and Voice's Advanced disclosure report activation, successful startup, first provisional result, explicit input end, confirmed transcript, first action and verified completion using monotonic time. No transcript or key is logged. Input-end timing is not acoustic word-end detection. Use Instruments Time Profiler, Allocations and Energy Log for CPU/memory and compare cold/warm physical sessions. [Recorded observations](REALTIME-VOICE.md#measurement) are individual runs; controlled physical-device and resource benchmarks remain outstanding.

The local build script selects a single valid development signing identity and derives its team from the public certificate; no personal identity is persisted. Ad-hoc fallback remains available. Stable signing reduces TCC churn during development but distribution still needs a release identity and notarization.

ProviderConnection owns asynchronous credential/verification state outside view lifetime. KeychainCredentials serializes Security.framework calls on a background queue; startup checks metadata with authentication UI disabled. Operation IDs prevent stale reads, network results and canceled requests from mutating newer state. Menu-bar lifecycle explicitly survives closing the final window and disables automatic background termination. Local diagnostics log phases and lifecycle only, never keys or raw responses.

## Display-safe capsule layout

VoicePanel owns window sizing. Its NSHostingView disables automatic intrinsic window sizing; CapsuleView reports the natural height of fixed-size vertical content explicitly. The panel anchors at a 14-point inset from the display’s visible frame, grows upward and clamps both dimensions to that usable rectangle. Shadow padding adds separation between the glass shell and screen edge. Root scrolling keeps unusually tall content reachable; existing text scrolling remains bounded. Display configuration changes recompute constraints, including when a selected monitor disappears. Layout uses AppKit logical points, without multiplying by display scale factors.

Requested document opening/revealing and application launches are reversible native tools and do not request a second Sotto approval. FilePolicy validates local paths and permits supported document/media formats and macOS application bundles. Script/installer types remain rejected. The trusted gate continues validating every call, and consequential tools retain their authorization boundary.
